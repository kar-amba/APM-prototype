# AGENTS.md — карта репозитория

> Это **оглавление**, а не энциклопедия. Здесь короткая навигация и ссылки на
> источники истины. Подробности живут в `docs/`. Принцип — прогрессивное
> раскрытие: начни отсюда, дальше иди по указателям.
>
> Файл `claude.md` — хард-линк на этот файл. Редактируй только `agents.md`.

## Что это за репозиторий

Прототип **APM ГлоуБайт** — веб-приложение, демонстрирующее целевой вид системы
управления надёжностью активов (EAM + APM). Реальных интеграций нет — внешние
источники данных (телеметрия оборудования, SCADA/IoT, ERP) **симулируются**.

Стадия: проектирование. Кода приложения пока нет.

## Источник истины — это репозиторий

Всё, что должно быть доступно агенту, живёт в репозитории в виде версионируемых
артефактов (markdown, схемы, планы, код). Если знание не в репозитории — для
агента его не существует. Не полагайся на внешний контекст (чаты, головы людей).

## Карта знаний (`docs/` — system of record)

```
AGENTS.md            ← ты здесь (карта)
claude.md            ← хард-линк на AGENTS.md
ARCHITECTURE.md      ← верхнеуровневая карта системы и слоёв
readme.md            ← краткое описание проекта
docs/
├── product/main.md          ← продуктовое видение (v1)
├── techstack/main.md        ← технологический стек (заполняется)
├── brandbook-template.html  ← дизайн-система (источник визуального стиля)
├── design-docs/
│   ├── index.md             ← каталог проектных документов + статус
│   └── core-beliefs.md      ← операционные принципы (golden principles)
├── exec-plans/
│   ├── index.md             ← как вести планы
│   ├── active/              ← активные планы работ
│   ├── completed/           ← завершённые планы
│   └── tech-debt-tracker.md ← реестр технического долга
└── references/
    └── index.md             ← внешние справочники (*-llms.txt) для агентов
```

## С чего начинать по типу задачи

- **Продукт / функциональность** → `docs/product/main.md`.
- **Архитектура / структура** → `ARCHITECTURE.md`.
- **Принципы работы и стиль** → `docs/design-docs/core-beliefs.md`.
- **Стек / инструменты** → `docs/techstack/main.md`.
- **Внешние библиотеки** → `docs/references/index.md` + актуальная документация.

## Рабочие нормы

- **Планы — артефакты первого класса.** Нетривиальную работу фиксируй в
  `docs/exec-plans/active/` и переноси в `completed/` по завершении.
- **Поддерживай документы в актуальном состоянии.** Меняешь поведение — обнови
  соответствующий документ в `docs/`. Стале́ные документы хуже их отсутствия.
- **Сохраняй существующую структуру и файлы**, если не сказано иначе.
- **CI/CD и автолинтеры пока не настроены** — это сознательно отложено.

## Правило по фронтенду

Если работаешь с фронт-ендом и задача связана с изменениями визуальной части, то
изучи `docs/brandbook-template.html` и следуй дизайн-системе.
