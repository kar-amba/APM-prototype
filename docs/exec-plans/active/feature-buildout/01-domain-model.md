# План: Доменная модель и Zod-схемы для всех сущностей v1

- Статус: active
- Дата: 2026-05-31

## Цель

Расширить `src/model` до полного набора сущностей продуктового видения v1, чтобы
последующие разделы строились на типизированных контрактах (а не на догадках).
Сейчас описаны только `FunctionalLocation`, `Asset` и общие enum.

## Контекст

- Модель данных v1: [`../../../product/main.md`](../../../product/main.md) (раздел 6).
- Текущая модель: `src/model/{common,functional-location,asset}.ts`.
- Принцип «валидируем границы данных» — core-belief №7.
- Слой репозитория: `src/data/repository.ts` (после добавления сущностей дополнить
  `AppRepository` соответствующими репозиториями).

## Шаги

- [ ] **Классификация и атрибуты:** `Classification`, `AttributeDefinition`
      (тип значения, единица измерения, диапазон), `AssetAttributeValue` (значение
      атрибута для актива). Связать с `Asset.classification`.
- [ ] **Статусные схемы:** `StatusScheme`, `Status`, `Transition`, ссылка на
      применимую сущность (assets/analyses/strategies/tasks/routes). Заменить
      «зашитый» `assetStatusSchema` на статусы из схемы (с миграцией текущих значений).
- [ ] **Стратегии и мероприятия:** `Strategy` (тип: реактивная/ППР/по состоянию/
      предиктивная), `MaintenanceTask` (интервал, привязка к активу/классу).
- [ ] **Маршруты и обходы:** `Route`, `RoutePoint`, `MeasurementPoint`/`ChecklistItem`
      (с допустимым диапазоном), `RoundExecution`, `Reading`.
- [ ] **Критичность:** `CriticalityAssessment` (последствия × вероятность, итоговый класс).
- [ ] **Дефекты и уведомления:** `Defect`, `Notification` (источник: обход/симулятор).
- [ ] **Справочные сущности:** `Manufacturer`, `OrgUnit` (цех/участок), `Person`,
      `UnitOfMeasure`, `Document`.
- [ ] Все сущности — через Zod-схемы, экспорт типов `z.infer`, ре-экспорт из
      `src/model/index.ts`.
- [ ] Расширить `AppRepository` интерфейсами репозиториев под новые сущности.
