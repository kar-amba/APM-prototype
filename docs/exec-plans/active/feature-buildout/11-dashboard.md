## Журнал решений

- 2026-06-07: доменная логика дашборда вынесена в `services/dashboard.ts`
  (чистые функции: `computeKpis`, `topCriticalAssets`, `recentDeviations`,
  `openDefectsList`, `defectsByDay`, `criticalityDistribution`,
  `roundsCompletion`/`roundsSummary`). UI грузит данные через репозиторий и
  считает сводки сервисом — единый источник правил, переиспользует
  `criticality.latestAssessmentByAsset` и `rounds.roundProgress`.
- 2026-06-07: KPI выбраны практичными для прототипа без журнала отказов —
  всего активов, готовность парка (% в работе по коду состояния схемы),
  открытые дефекты (+ критические), отклонения в замерах. MTBF/доступность
  отложены (нет истории отказов).
- 2026-06-07: графики — Recharts (`AreaChart` тренда дефектов за 14 дней,
  `BarChart` распределения по критичности с `Cell` на семантических токенах),
  вынесены в `DefectsTrendChart`/`CriticalityDistributionChart`. Цвета — через
  CSS-переменные брендбука (`var(--color-*)`) как в `ReadingTrendChart`.
- 2026-06-07: «живость» обеспечена зависимостью загрузки от `revision` стора
  данных — симулятор телеметрии после каждого тика делает `bumpRevision`, и
  виджеты дашборда перечитывают репозиторий (отклонения/дефекты/KPI растут).
