# План: Обходы и маршруты

- Статус: completed
- Дата: 2026-05-31

## Цель

Наполнить раздел «Обходы и маршруты» (`src/features/rounds`) — конструктор
маршрутов, экран выполнения обхода и журнал замеров. Сейчас это заглушка.

## Контекст

- Маршруты и обходы: [`../../../product/main.md`](../../../product/main.md)
  (раздел 4, п. 5; раздел 5 — карточка, вкладка «Обходы и замеры»).
- Симулируемая «интеграция через обходы»: замер вне диапазона → дефект/уведомление
  (раздел 2, п. 6).
- Зависит от: [`01-domain-model.md`](01-domain-model.md) (`Route`, `RoutePoint`,
  `MeasurementPoint`, `RoundExecution`, `Reading`),
  [`03-persistence-and-crud.md`](03-persistence-and-crud.md).

## Шаги

- [x] Конструктор маршрута: набор точек контроля (замеры/чек-листы) с допустимыми
      диапазонами; привязка к активам.
- [x] Экран выполнения обхода (мобильно-подобный): ввод замеров по точкам.
- [x] Валидация замера: значение вне диапазона помечается отклонением и **порождает
      дефект/уведомление** (общий сервис с симулятором, см. [`10-telemetry-simulation.md`](10-telemetry-simulation.md)).
- [x] Журнал замеров и история по точкам; отображение на вкладке «Обходы и замеры»
      карточки актива (тренды — Recharts).
- [x] i18n + визуал на токенах брендбука.

## Журнал решений

- 2026-06-07: раздел выполнен. Добавлен сервис `services/rounds.ts`: порядок
      точек маршрута, выборки замеров, валидация замера по диапазону
      (`isReadingDeviation`), тренд числовых замеров и **фабрики дефекта/
      уведомления из отклонения** (`buildDeviationDefect`/
      `buildDeviationNotification`) — фабрики вынесены в сервис намеренно, чтобы
      их переиспользовал симулятор телеметрии (план 10). Раздел
      `features/rounds`: три вкладки — «Маршруты» (конструктор: список маршрутов +
      CRUD точек контроля с диапазонами), «Выполнение обхода» (старт обхода по
      маршруту + мобильно-подобный ввод замеров по точкам; замер вне диапазона
      создаёт `Defect` + `Notification`), «Журнал замеров» (история всех
      измерений). Тренды — Recharts (`ReadingTrendChart`, `ResponsiveContainer` +
      `LineChart` с опорными линиями min/max). Вкладка «Обходы и замеры» карточки
      актива (`AssetRoundsTab`) показывает точки контроля актива, тренд выбранной
      точки и историю замеров. Чек-листы трактуются как отклонение при результате
      «нет». i18n-ключи `rounds.*`, `routePointKind.*`, `roundStatus.*`,
      `defectStatus.*`, `defectSource.*`, `assetCard.roundsTab.*`.

## Критерии готовности

- [x] Замер вне диапазона создаёт дефект/уведомление.
- [x] История замеров видна в карточке актива.
- [x] `npm run lint` и `npm run build` проходят.
