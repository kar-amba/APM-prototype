# План: Справочники

- Статус: active
- Дата: 2026-05-31

## Цель

Наполнить раздел «Справочники» (`src/features/catalogs`) управлением
классификаторами и опорными сущностями. Сейчас это заглушка.

## Контекст

- Состав справочников: [`../../../product/main.md`](../../../product/main.md)
  (раздел 4, п. 8).
- Зависит от: [`01-domain-model.md`](01-domain-model.md) (`Classification`,
  `AttributeDefinition`, `Manufacturer`, `OrgUnit`, `Person`, `UnitOfMeasure`),
  [`03-persistence-and-crud.md`](03-persistence-and-crud.md) (CRUD-инфраструктура).

## Шаги

- [x] Навигация по справочникам — табы: Классификатор, Производители,
      Оргструктура, Персонал, Единицы измерения (`Tabs` из `shared/ui`).
- [x] **Классификатор** с атрибутами класса: дерево классов (отступы по глубине)
      + редактор наборов атрибутов (тип, единица измерения, диапазон, варианты).
- [x] CRUD по записям справочников через формы RHF + Zod (`forms.tsx`,
      generic-таблица `CatalogTable`).
- [x] Связи: классы используются активами; производитель — datalist из
      справочника в форме актива; атрибуты класса подтягиваются в карточку
      актива (вкладка «Паспорт и атрибуты»).
- [x] i18n + визуал на токенах брендбука.

## Журнал решений

- 2026-06-04: классификатор реализован плоским деревом с отступами по глубине
      (без drag&drop) — достаточно для прототипа и проще `react-arborist`.
- 2026-06-04: атрибут класса редактируется собственной form-схемой
      (`optionsText` → массив `options`, числовые min/max через `setValueAs`),
      т.к. поле `options` в модели — массив, а в форме удобнее строка.
- 2026-06-04: производитель в форме актива — `datalist` (выбор из справочника
      с возможностью ручного ввода), чтобы не ломать существующие строковые
      значения. Полный переход `owner`/`planner` на ссылки в справочники
      отложен (хранятся как строки).

## Критерии готовности

      формах активов.
- [x] Классификатор задаёт атрибуты, которые подтягиваются в карточку актива.
- [x] `pnpm lint` и `pnpm build` проходят.
