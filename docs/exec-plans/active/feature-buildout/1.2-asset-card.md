## Цель

Рефакторинг UX и представления карточки актива в реестре и отдельном маршруте:
два уровня детализации (краткая панель в реестре + полная карточка в новой вкладке
с сохранением оболочки приложения), виджеты связанных сущностей на полной карточке.

Ожидаемый результат — реестр остаётся рабочим местом для обзора списка, полная
карточка открывается для глубокой работы без потери контекста навигации (sidebar,
верхняя панель, роль).

## Целевое поведение (UX)

### AC-1. Ссылка на название актива → полная карточка в той же вкладке

- В колонке «Наименование» журнала реестра (`AssetTable`) имя актива — **ссылка**
  (не срабатывает выбор строки).
- По клику (обычному, левой кнопкой) **в той же вкладке** выполняется переход на
  маршрут полной карточки (например `/assets/:assetId`) — это **основной паттерн**.
  Открытие в новой вкладке — **не** поведение по умолчанию.
- Маршрут — **дочерний** `AppShell`: видны левое меню, верхняя панель, переключатель
  роли; меняется только рабочая область (полная карточка). In-memory режим (`seeds`)
  сохраняется, т.к. SPA не перезагружается.
- Хлебные крошки / заголовок раздела отражают переход: Реестр → карточка актива
  (код + наименование).
- Возврат к списку — штатной навигацией браузера/крошками (история сохраняется,
  отдельной вкладки не появляется).

### AC-1a. Открытие в новой вкладке — только по явной команде из контекстного меню

- Новая вкладка браузера с полной карточки (`target="_blank"`, тот же маршрут
  `/assets/:assetId`) открывается **только по явной команде пользователя**: пункт
  **контекстного меню** строки/имени актива (например «Открыть в новой вкладке»).
- Стандартные жесты браузера (Ctrl/Cmd+клик, средняя кнопка по ссылке) сохраняются
  «бесплатно», т.к. имя — настоящий `<a href>`; их специально не подавляем.
- Контекстное меню — переиспользуемый компонент (по брендбуку); минимальный набор
  пунктов в 1.2: «Открыть» (та же вкладка) и «Открыть в новой вкладке». Прочие
  действия (редактировать/удалить) — опционально, по решению при реализации.

### AC-2. Клик по строке (не по ссылке имени) → краткая карточка под реестром

- Клик по строке таблицы (вне ссылки имени) **не** открывает правую колонку
  полной карточки.
- Layout реестра: сверху две панели в ряд — **«Иерархия»** и **«Реестр активов»**
  (таблица); снизу — **краткая карточка** выбранного актива (если строка выбрана).
- Краткая карточка содержит основные поля: код, наименование, класс, место,
  статус, критичность, производитель/модель (сжатый набор из обзора).
- В краткой карточке — явная ссылка/кнопка «Открыть карточку»: переход **в той же
  вкладке** на `/assets/:assetId` (тот же маршрут, что и у имени актива). Открытие
  в новой вкладке — только через контекстное меню (см. AC-1a).
- Повторный клик по выбранной строке или снятие выбора — по согласованному правилу
  (скрыть панель или оставить последний выбор); зафиксировать в журнале при реализации.

### AC-3. Полная карточка — виджеты связанных сущностей

- На полной карточке (маршрут `/assets/:assetId` и при необходимости вкладка
  «Обзор») — блок **виджетов** связанных сущностей:
  - стратегии и мероприятия (назначенная стратегия, ближайшие/просроченные задачи);
  - обходы и замеры (последний обход, открытые замечания);
  - анализы критичности (последняя оценка);
  - дефекты / уведомления (если есть в сидах);
  - при необходимости — заглушка «Нет данных» с понятным текстом до фазы 2.
- Виджеты — переиспользуемые компоненты (`AssetRelatedWidgets` или по одному файлу
  на тип), данные через репозиторий/сервисы, без прямого доступа UI к хранилищу.
- Вкладки карточки (`AssetDetails` / `AssetCardPage`) сохраняются; виджеты на обзоре
  дополняют вкладки «Стратегия», «Обходы» и т.д., а не дублируют их полностью.

  Открытие в новой вкладке оставляем **только по явной команде** пользователя из
