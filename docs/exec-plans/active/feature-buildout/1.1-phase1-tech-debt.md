## Шаги

### TD-1. Статусы активов через статусную схему (влияние: сред)

- [x] В модели `Asset`: заменить `status: assetStatusSchema` на `statusId: string`
      (ссылка на состояние схемы `ss-asset`). Денормализацию `statusCode` не вводили —
      справочник состояний мал, lookup по карте `statusById` дёшев.
- [x] Обновить сиды активов: `statusId` → id из `statusSeed` схемы `ss-asset`.
- [x] Сервис `status-flow`: добавлен `resolveAssetStatus()` (схема, текущее
      состояние, допустимые переходы). Смена статуса в реестре проверяет переход.
- [x] Реестр: форма/карточка/таблица — бейджи (тон+имя) и переходы из `Status`
      репозитория, не по `assetStatus` i18n-ключам enum.
- [x] Поиск: фильтр «Статус» — по состояниям схемы актива (`statusId`).
- [x] `assetStatusSchema` помечен `@deprecated` в `common.ts`; прямые импорты в
      UI/формах убраны (остаётся только для миграции).
- [x] Миграция данных в localStorage/Dexie: адаптер `data/migrations.ts`
      (`migrateAsset`), применяется на чтении в репозиториях (`migrate` в
      `EntityDescriptor`): code → `statusId`.

### TD-2. Владелец и планировщик — ссылки на справочники (влияние: низк)

- [x] В модели `Asset`: `ownerId` (`OrgUnit`) / `plannerId` (`Person`), опциональные;
      строковые `owner`/`planner` убраны (миграция — в `migrateAsset`).
- [x] Сиды: `owner` (коды ДОЦ/ППЦ/…) → `org-*`; `planner` (ФИО) → `pr-*`.
- [x] Форма актива: выпадающие списки `OrgUnit` (владелец) и `Person` (планировщик).
- [x] Поиск: фильтры владелец/планировщик — из `orgUnits`/`persons`, не distinct.
- [x] Карточка актива (обзор): ФИО планировщика и название подразделения из справочников.

### TD-3. Код-сплиттинг маршрутов (влияние: низ)

## Журнал решений

- 2026-06-04: фаза **1.1** введена в дорожную карту между фазами 1 и 2 по запросу
  команды — техдолг не смешиваем с новыми разделами APM.
- 2026-06-04: в 1.1 входят только три записи из `tech-debt-tracker.md` на дату
  завершения фазы 1; остальные долги добавляются в трекер и при необходимости — в
  отдельные мини-фазы.
- 2026-06-07: **TD-2 — отклонение от формулировки плана.** План предлагал и
  `owner`, и `planner` свести к `Person`. По факту в сидах `owner` — это **код
  подразделения** (ДОЦ/ППЦ/ПРЦ/ЭНЦ), а `planner` — ФИО. Поэтому `ownerId` ссылается
  на **`OrgUnit`**, а `plannerId` — на **`Person`**. Так вернее данным и продукту.
- 2026-06-07: **миграция вынесена в дескриптор датасета.** `EntityDescriptor`
  получил необязательный `migrate(raw)`, применяемый на чтении во всех
  репозиториях (in-memory/localStorage/Dexie) перед Zod-валидацией. Для активов —
  `migrateAsset` из `data/migrations.ts`. Это «адаптер на границе хранилища» без
  связывания обобщённого репозитория со спецификой активов.
- 2026-06-07: **TD-3 — конфиг разбиения вендоров.** В Vite 8 (rolldown)
  `output.manualChunks` и `output.advancedChunks` устарели (проверено по докам
  Context7 и предупреждению сборки) — использован
  `build.rolldownOptions.output.codeSplitting.groups`.
