# Дорожная карта: обвязка каркаса прототипа APM ГлоуБайт

- Статус: active
- Дата: 2026-05-31

## Назначение

Каркас готов (см. [`../skeleton-scaffold.md`](../skeleton-scaffold.md)): оболочка,
роутер на 8 разделов, дизайн-токены, i18n, слой репозитория (in-memory) и сквозной
срез «Реестр активов» (дерево + таблица + карточка). Эта дорожная карта описывает
**дальнейшее наращивание функционала** — превращение каркаса в полностью
интерактивный прототип целевого вида из [`../../../product/main.md`](../../../product/main.md).

Это **индекс**: он задаёт фазы, последовательность и зависимости. Конкретная работа
вынесена в отдельные лёгкие планы в этой же директории — по одному на рабочий блок.
Каждый план самодостаточен, чтобы его можно было взять в отдельной сессии агента.

## Принципы наращивания

- **Слои не нарушаем:** `Модель → Данные → Сервисы → UI` (см.
  [`../../../../ARCHITECTURE.md`](../../../../ARCHITECTURE.md)).
- **Границы данных — через Zod:** новые сущности описываем схемами в `src/model`.
- **Доступ к данным — только через репозиторий:** UI не знает о хранилище.
- **Симуляция вместо интеграций** (core-belief №5): «телеметрия» — локальный сервис.
- **Единый визуальный язык** — дизайн-система `../../../brandbook-template.html`,
  переиспользуем готовые обёртки `src/shared/ui` и токены.
- **Все строки — через i18n** (`src/shared/i18n`).
- **Переиспользуем паттерн «дерево + таблица + детали»** из `asset-registry` для
  разделов с активами.

```
           ├─> 03 хранение+CRUD ────────────────┤

           ├─> 04 поиск                          │
           ├─> 05 справочники (классы/атрибуты) ─> уточняют 01/02
           │
           └─> [фаза 1 ✅] ──> 1.1 техдолг ──> 1.2 карточка актива ──> [перед фазой 2]
                                    │
           ├─> 07 критичность ◄────┘ (виджеты 1.2 наполняются в 07–09)
           ├─> 08 стратегии
           └─> 09 обходы ──> 10 симулятор ──> дефекты/уведомления ──> 11 дашборд
                                                  12 роли — поверх всех разделов
```

## Глобальные критерии готовности обвязки

- [ ] Все 8 разделов перестали быть заглушками и работают на данных через репозиторий.
- [ ] Поддержан интерактивный CRUD по ключевым сущностям (RHF + Zod).
- [ ] Работает переключение режима хранения и сброс к исходным сидам.
- [ ] Симулятор телеметрии генерирует отклонения → дефекты/уведомления → видно на дашборде.
- [ ] Переключатель роли меняет акценты интерфейса.
- [ ] `pnpm lint` и `pnpm build` проходят без ошибок.
- [ ] Документы (`ARCHITECTURE.md`, `techstack`, `product`) актуализированы под факт.
