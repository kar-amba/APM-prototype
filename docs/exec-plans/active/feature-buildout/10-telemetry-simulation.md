## Шаги

- [x] Сервис-симулятор на таймерах: генерирует показания по точкам контроля во
      времени (тренды + шум), сохраняет ряды через репозиторий.
- [x] Логика отклонений: значение вне допустимого диапазона → `Defect`/`Notification`

- [x] Управление симулятором: старт/стоп/скорость (в системных настройках).
- [x] Уведомления видны в оболочке (индикатор в верхней панели). Дашборд —
      следующий шаг (план 11), индикатор уже работает на «живых» данных.

## Журнал решений

- 2026-06-07: реализовано. Чистая доменная логика генерации — `services/telemetry.ts`
  (`measurementPoints`, `nextValue` со случайным блужданием и возвратом к центру
  диапазона, `shouldDeviate`, скорости `slow/normal/fast`, ограничение роста
  замеров на точку). Императивный контроллер (таймер + запись через репозиторий +
  `bumpRevision`) вынесен в `store/simulatorStore.ts`, чтобы не помещать побочные
  эффекты в чистый сервис. Замеры симулятора — `Reading` без `roundExecutionId`
  (поле сделано опциональным) с префиксом id `rd-sim-`; в ручной «Журнал замеров»
  раздела «Обходы» они не попадают, но питают тренды на карточке актива. Дефект из
  отклонения порождается общей фабрикой `buildDeviationDefect` (добавлен параметр
  `source`, для телеметрии — `simulator`). Управление — секция в системных
  настройках (старт/стоп/скорость + статистика). Индикатор уведомлений с числом
  непрочитанных и панелью добавлен в верхнюю панель оболочки
  (`app/NotificationsMenu.tsx`).
