# План 04: Уровни риска и цветовые зоны

- Статус: active
- Дата: 2026-06-08

## Цель

Дать UI для настройки **уровней риска и цветовых зон** матрицы: именованные уровни
(напр. низкий/средний/высокий/критический/экстремальный), цвет/тон зоны и **пороги
перехода** между зонами по риск-баллу. Поддержать два режима: пороги по баллу
(`rankMode='product'|'sum'`) и явная окраска ячеек (`rankMode='explicit'`).

## Контекст

- `RiskLevel` (`code`, `name`, `tone`, `color?`, `order`, `scoreFrom`, `scoreTo`,
  `actionHint?`) и `RiskMatrixCell` — встроены в `RiskMatrix`
  ([`01-domain-model.md`](01-domain-model.md)). Поэтому уровни риска
  настраиваются **в контексте конкретной матрицы** (вкладка/секция матрицы),
  а не как глобальный справочник.
- Тоны зон — `statusToneSchema` (success/info/warning/error/default); опциональный
  hex `color` для палитр с 5+ зонами (решение в [`index.md`](index.md)).
- Пороговая классификация перекликается с заменяемой
  `criticalityLevelFromScore` (`src/services/criticality.ts`).

## Шаги

- [ ] Редактор уровней риска матрицы (`RiskLevelsEditor`, RHF `useFieldArray`):
      строка уровня — `name`, `tone` (выбор) + опц. `color`, `scoreFrom`, `scoreTo`,
      `actionHint`. Кнопки добавить/удалить/переупорядочить; `order` авто.
- [ ] Сервис `src/services/risk-matrix.ts` (чистые функции, единый источник правил):
      - `riskScore(consequenceOrder, probabilityOrder, rankMode)` —
        произведение/сумма;
      - `riskLevelForScore(matrix, score)` — поиск зоны по `scoreFrom/scoreTo`;
      - `riskLevelForCell(matrix, c, p)` — с учётом `rankMode` (`explicit` →
        смотреть `cells`);
      - `validateZones(matrix)` — пороги не пересекаются и **покрывают весь
        диапазон** возможных баллов (от min до max по размеру шкал); возвращает
        список проблем для показа в форме.
- [ ] Режим `explicit`: редактирование цвета ячейки прямо на сетке предпросмотра —
      клик по ячейке назначает ей уровень риска (план 05 рендерит сетку, здесь —
      логика назначения и хранение в `cells`).
- [ ] Живой предпросмотр: при изменении порогов/назначений сетка матрицы
      перекрашивается немедленно (использовать сервис, без записи до «Сохранить»).
- [ ] Валидация на сохранении: нет «дыр» и пересечений порогов; каждая зона имеет
      уникальный `order`; хотя бы 2 зоны.
- [ ] i18n (`riskConfig.zones.*`) + визуал на токенах брендбука.

## Журнал решений

- 2026-06-08: уровни риска привязаны к матрице (а не глобальны), т.к. у разных
  видов анализа разные шкалы баллов и число зон. Общая «палитра» при желании
  достигается копированием матрицы-шаблона (план 05).

## Критерии готовности

- [ ] Уровни риска и зоны настраиваются (имя, тон/цвет, пороги, рекомендация).
- [ ] Пороги валидируются на непрерывность и непересечение; ошибки показываются.
- [ ] В режиме `explicit` ячейкам можно назначать зоны вручную.
- [ ] Сетка предпросмотра перекрашивается вживую; `npm run lint`/`build` проходят.
