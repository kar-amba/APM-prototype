# План 02: Конфигуратор шкал

- Статус: active
- Дата: 2026-06-08

## Цель

Дать пользователю UI для настройки **шкал вероятности, последствий, критичности и
ранга риска**: создание/редактирование шкалы, управление её уровнями (число
уровней, код, подпись, описание, числовой/текстовый «якорь»). Шкалы — переиспользуемые
строительные блоки матриц (план 05) и категорий (план 03).

## Контекст

- Сущности `RiskScale` / `RiskScaleLevel`: [`01-domain-model.md`](01-domain-model.md).
- Раздел/навигация конфигуратора «Матрицы риска» (см. открытый вопрос в
  [`index.md`](index.md)); создаётся в первом из планов 02–05, остальные
  добавляют вкладки.
- Паттерн CRUD-конфигуратора: `src/features/status-schemes` (конструктор
  состояний/переходов) и `src/features/catalogs` — переиспользовать подход
  (список + форма в `Modal`, RHF + Zod, `useFieldArray` для дочерних строк).
- Обёртки UI: `src/shared/ui` (Button, Badge, Card, Tabs, Modal, EmptyState).
- i18n-ключи `riskConfig.scales.*`, `riskScaleKind.*` в `src/shared/i18n`.

## Шаги

- [ ] Завести раздел «Матрицы риска» в `src/features/risk-config/` и пункт навигации
      (`src/app`), маршрут под `AppShell`, ленивый (`React.lazy`) как остальные.
      Внутри — `Tabs`: «Шкалы», «Категории последствий», «Уровни риска», «Матрицы».
- [ ] Вкладка «Шкалы»: список шкал, сгруппированный/фильтруемый по `kind`
      (вероятность/последствия/критичность/ранг) с бейджем вида.
- [ ] Форма шкалы (`RiskScaleForm`, RHF + Zod, в `Modal`):
      - поля `code`, `name`, `kind`, `description`;
      - редактор уровней через `useFieldArray`: добавить/удалить/переупорядочить
        уровень, поля `label`, `description`, `anchor`; `order` пересчитывается
        автоматически; запрет < 2 уровней.
- [ ] Валидация: уникальность `code` шкалы; уникальность/непрерывность `order`
      уровней (использовать `superRefine` из модели); запрет удаления шкалы,
      на которую ссылается матрица или категория (показать предупреждение).
- [ ] Все операции — через `useRepository('riskScales')`; после изменения —
      `bumpRevision` стора данных (как в существующих разделах).
- [ ] i18n + визуал на токенах брендбука; предпросмотр шкалы (уровни 1…N лесенкой
      с подписями и якорями).

## Критерии готовности

- [ ] Можно создать, отредактировать и удалить шкалу любого из четырёх видов.
- [ ] Уровни шкалы редактируются (добавление/удаление/порядок) с валидацией.
- [ ] Удаление используемой шкалы заблокировано с понятным сообщением.
- [ ] `npm run lint` и `npm run build` проходят.
