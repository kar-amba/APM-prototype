# План 03: Категории последствий

- Статус: active
- Дата: 2026-06-08

## Цель

Дать UI для настройки **категорий последствий** — производство, безопасность,
экология, качество, финансы (плюс пользовательские). Для каждой категории
настраивается описание тяжести по уровням выбранной шкалы последствий, признак
активности, порядок и (опционально) вес для агрегации.

## Контекст

- Сущность `ConsequenceCategory` + `descriptors`: [`01-domain-model.md`](01-domain-model.md).
- Зависит от шкал последствий из [`02-scales-config.md`](02-scales-config.md)
  (категория ссылается на `consequenceScaleId`, `kind='consequence'`).
- Размещение — вкладка «Категории последствий» в разделе «Матрицы риска»
  (раздел заводится в плане 02).
- Агрегация категорий на ось последствий матрицы (`max`/`weighted`) определяется в
  матрице (план 05); здесь — только настройка самих категорий.

## Шаги

- [ ] Сидовые пять категорий (производство/безопасность/экология/качество/финансы)
      выводятся списком с бейджем «вкл/выкл» и кнопкой добавить свою.
- [ ] Форма категории (`ConsequenceCategoryForm`, RHF + Zod, в `Modal`):
      - `code` (для известных — выбор из констант, для своей — ввод), `name`,
        `description`, `enabled`, `order`, `weight?`;
      - выбор `consequenceScaleId` (только шкалы `kind='consequence'`);
      - таблица описаний: по строке на каждый уровень выбранной шкалы
        (`scaleOrder` + `description`), автоматически синхронизируется с числом
        уровней шкалы (`useFieldArray`).
- [ ] Валидация: уникальность `code`; `descriptors` покрывают все уровни выбранной
      шкалы; `weight` ≥ 0 (если задан).
- [ ] При смене шкалы у категории — пересобрать строки описаний, по возможности
      сохранив введённые тексты для совпадающих `scaleOrder`.
- [ ] Операции через `useRepository('consequenceCategories')` + `bumpRevision`.
- [ ] i18n (`riskConfig.categories.*`, `consequenceCategory.*`) + визуал на токенах.
      Каждой стандартной категории — узнаваемая иконка из `lucide-react`
      (производство, безопасность/щит, экология/лист, качество, финансы).

## Журнал решений

- 2026-06-08: описание уровней тяжести храним в категории (`descriptors`), а сами
  числовые уровни — в общей шкале последствий. Так одна шкала переиспользуется
  несколькими категориями, а смысл уровня («что именно произойдёт») задаётся
  отдельно для каждой категории — это стандартный приём отраслевых матриц рисков.

## Критерии готовности

- [ ] Пять стандартных категорий настраиваются; можно добавить пользовательскую.
- [ ] Для каждой категории задаётся описание всех уровней тяжести по шкале.
- [ ] Включение/выключение категории отражается в списке.
- [ ] `npm run lint` и `npm run build` проходят.
