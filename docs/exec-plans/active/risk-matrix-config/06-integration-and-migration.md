# План 06: Интеграция и переход

- Статус: active
- Дата: 2026-06-08

## Цель

Перевести существующий раздел «Анализ критичности» и рекомендации стратегий на
**конфигурируемую матрицу по умолчанию** (вид анализа ACA), убрать жёстко зашитые
шкалу и пороги, мигрировать старые оценки и актуализировать документацию. Это
финальный блок дорожной карты — связывает конфигуратор с рабочим разделом.

## Контекст

- Заменяемая жёсткая логика: `src/services/criticality.ts`
  (`CRITICALITY_SCALE`, `riskScore`, `criticalityLevelFromScore`,
  `recommendedStrategyType`) и форма `src/features/criticality/CriticalityForm.tsx`
  (оси 1…5 захардкожены), матрица `CriticalityMatrix.tsx`.
- Новый сервис правил `src/services/risk-matrix.ts` (план 04).
- Матрица ACA по умолчанию из сидов (план 01) воспроизводит текущие пороги.
- Паттерн миграции на чтении: `src/data/migrations.ts` (`migrate` в
  `EntityDescriptor`), описан в `ARCHITECTURE.md`.

## Шаги

- [ ] Расширить `CriticalityAssessment` (`src/model/criticality.ts`) — опционально:
      - `matrixId?` (какая матрица применялась; по умолчанию — текущая ACA);
      - `consequenceByCategory?: { categoryCode, order }[]` (оценка по категориям);
      - оставить `consequence`/`probability`/`score`/`level` для совместимости.
      Все новые поля — опциональны, чтобы старые записи оставались валидны.
- [ ] `services/criticality.ts`: вычисления делегировать `services/risk-matrix.ts`,
      используя **матрицу ACA по умолчанию** вместо констант. Размер осей, пороги
      зон, рекомендация стратегии — из конфигурации, а не из захардкоженных чисел.
      Сохранить тонкие совместимые обёртки или пометить старые как `@deprecated`.
- [ ] `CriticalityForm`: оси `<select>` строить из уровней шкал матрицы ACA
      (подписи/якоря из конфигурации); если включены категории последствий — ввод
      тяжести по категориям с агрегацией (max/weighted) в итоговую ось последствий;
      предпросмотр класса/зоны — через сервис.
- [ ] `CriticalityMatrix`: размер сетки и окраска — из матрицы ACA по умолчанию
      (а не фиксированные 5×5/пороги).
- [ ] Рекомендация типа стратегии (`recommendedStrategyType`, используется в
      `services/strategies.ts`) — брать из зоны риска матрицы (`actionHint`/
      сопоставление зона→тип стратегии), а не из захардкоженной карты.
- [ ] Миграция `data/migrations.ts`: для старых `CriticalityAssessment` проставлять
      `matrixId` матрицы ACA по умолчанию; значения 1…5 совместимы по построению.
      Подключить через `migrate` в `datasets.ts`. Проверить режимы
      localStorage/Dexie и сброс к сидам.
- [ ] Актуализировать документацию (core-belief №4):
      - `docs/product/main.md` — раздел 4 (карта разделов) и 6 (модель данных):
        добавить конфигуратор матриц риска и новые сущности; «Анализ критичности»
        описать как потребителя матрицы ACA;
      - `ARCHITECTURE.md` — домены и слой сервисов (`risk-matrix.ts`);
      - `docs/techstack/main.md` — структура `src/features/risk-config`,
        новые `src/model/risk-matrix.ts` и репозитории.
- [ ] По завершении всей карты — перенести планы в `docs/exec-plans/completed/` и
      обновить `docs/exec-plans/index.md` (статусы).
