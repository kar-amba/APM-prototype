## Закрытые в фазе 1.1 (2026-06-07)

- **TD-1.** `Asset.status` (enum) → `Asset.statusId` (ссылка на `Status` схемы
  `ss-asset`). Тон/имя бейджа берутся из состояния схемы. Смена статуса
  валидируется переходами через `services/status-flow.ts`
  (`resolveAssetStatus`). Миграция старых записей localStorage/Dexie — адаптер
  `data/migrations.ts` (`migrateAsset`) на границе хранилища.
- **TD-2.** `owner`/`planner` (строки) → `Asset.ownerId` (`OrgUnit`) и
  `Asset.plannerId` (`Person`). Формы реестра и фильтры поиска используют
  справочники. *Решение:* `owner` сопоставлен с **`OrgUnit`** (в сидах значения —
  коды подразделений: ДОЦ/ППЦ/ПРЦ/ЭНЦ), `planner` — с **`Person`** (ФИО). План
  1.1 формулировал оба как `Person`; отклонение зафиксировано здесь и в журнале
  плана, т.к. данные сидов это диктуют.
- **TD-3.** Код-сплиттинг маршрутов: `React.lazy` + общий `Suspense` в
  `AppShell`. Вендоры разнесены через `build.rolldownOptions.output.codeSplitting`
  (Vite 8 / rolldown; `manualChunks`/`advancedChunks` устарели). `pnpm build` без
  предупреждения о чанке > 500 kB.
