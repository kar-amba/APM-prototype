# Технологический стек прототипа APM ГлоуБайт

> Верхнеуровневый выбор технологий под концепцию из
> [`../product/conceptual-product.md`](../product/conceptual-product.md) и
> [`../product/main.md`](../product/main.md). Стек — популярный, современный и
> «понятный агенту» (см. `../design-docs/core-beliefs.md`).
>
> Точные версии перед реализацией сверяй через Context7 и ставь последние
> стабильные.

## Принципы выбора

- **Популярные и стабильные технологии** с большой экосистемой и хорошей
  документацией — их легко осмыслить и поддерживать.
- **Фронтенд-ориентированность**: в v1 бэкенда нет, данные локальные (см. режимы
  хранения ниже).
- **Валидация границ данных** типами и схемами (Zod) — никаких «угаданных» форм.
- **Опора на готовую дизайн-систему** из `../brandbook-template.html` (CSS-токены),
  без её переписывания.

## Подробнее по слоям

### База: React + TypeScript + Vite
Современный и самый распространённый стек для SPA. Vite даёт быстрый дев-сервер и
простую сборку. TypeScript обеспечивает типобезопасность и «легибельность» кода.

### Менеджер пакетов и Node
**pnpm** (быстрый, экономный; npm — допустимая альтернатива). Node.js — актуальная
LTS-версия.

### Маршрутизация
**React Router** — навигация между разделами из sidebar, вложенные маршруты для
карточки актива и вкладок.

### Состояние приложения
**Zustand** — лёгкое и популярное хранилище для UI-состояния (текущая роль, режим
хранения, фильтры, выбранные узлы дерева). Серверного состояния нет, поэтому
тяжёлые решения не нужны.

### Формы и валидация
**React Hook Form** для форм CRUD + **Zod** для схем и валидации на границах
(ввод форм, парсинг сидов, данные симулятора). Прямо реализует принцип «валидируем
границы данных».

### Таблицы и дерево
- **TanStack Table** — headless-таблицы реестра (сортировка, фильтры, колонки
  статусов/критичности), стилизуются классами брендбука.
- **react-arborist** — дерево иерархии активов; при желании заменяется собственным
  лёгким компонентом.

### Графики
**Recharts** — KPI-плитки дашборда, тренды замеров и истории показаний. Простой и
популярный, декларативный API.

### Стилизация и дизайн-система
**CSS Modules** для изоляции стилей компонентов поверх **CSS-токенов из брендбука**
(`--color-*`, `--space-*`, типографика). Готовые классы (`.btn`, `.card`, `.badge`,
`.table` и т.д.) переиспользуются. Tailwind сознательно не вводим, чтобы не
дублировать уже существующую дизайн-систему.

### Иконки
**lucide-react** — современный, обширный и лёгкий набор иконок.

### Локализация
**react-i18next** — строки интерфейса вынесены в ресурсы; русский — основной язык,
структура готова к добавлению переводов.

## Данные и симуляция

### Абстракция хранения (репозиторий)
Доступ к данным идёт через слой репозиториев с единым интерфейсом. Реализации
переключаются **системной настройкой** (см. `conceptual-product.md`):

1. **In-memory** — данные в памяти, сброс при перезагрузке.
2. **Локально в браузере** — localStorage или IndexedDB (через **Dexie**),
   изменения сохраняются между сессиями.
3. **Сиды (по умолчанию)** — загрузка предзаполненных наборов с возможностью
   **сброса к исходному состоянию**.
4. **База данных** — интерфейс-**заготовка**, в v1 не реализуется.

Остальной код зависит только от интерфейса репозитория, а не от конкретного
хранилища.

### Сиды демо-предприятия
Предзаполненные данные (металлургия/обогащение) — типизированные TS/JSON-наборы,
валидируемые через Zod при загрузке.

### Симуляция «телеметрии»
Отдельный сервис-симулятор на таймерах: обновляет показания во времени и
периодически выдаёт отклонения, которые порождают дефекты/уведомления. История
замеров хранится как предзаполненные ряды. Внешних библиотек не требует.

### Утилиты
**date-fns** — работа с датами/интервалами ТОиР; **nanoid** — генерация
идентификаторов сущностей.

## Дев-инструменты и структура

### Инструменты разработки
**ESLint + Prettier** — единый стиль и базовые проверки. **Vitest + React Testing
Library** — для тестов (по мере необходимости). CI/CD пока не настраивается.

### Структура проекта (фактическая)
Организация по слоям/фичам с однонаправленными зависимостями
(`Модель → Данные → Сервисы → UI`), см. `../../ARCHITECTURE.md`.

```
src/
├── model/            # типы и Zod-схемы по сущностям v1
│   ├── common, functional-location, asset, classification, status-scheme,
│   │   maintenance, rounds, criticality, reliability, catalog
│   └── index.ts      # ре-экспорт
├── data/             # слой доступа к данным
│   ├── repository.ts # интерфейс Repository<T> + AppRepository
│   ├── datasets.ts   # единый реестр датасетов (ключ + схема + сид)
│   ├── in-memory/    # InMemoryRepository
│   ├── local-storage/# LocalStorageRepository (Zod при чтении)
│   ├── dexie/        # DexieRepository (IndexedDB)
│   ├── mock/         # тематические сиды демо-предприятия + index.ts
│   └── index.ts      # фабрика по режиму, getAppRepository/resetAppRepository
├── services/         # бизнес-логика (задел, пока пусто)
├── store/            # Zustand: uiStore (роль), dataStore (режим хранения + useRepository)
├── shared/
│   ├── styles/       # tokens.css + global.css (классы брендбука)
│   ├── ui/           # обёртки: Button, Badge, Card, Tabs, EmptyState, Modal
│   └── i18n/         # react-i18next + locales/ru.json
├── app/              # оболочка: AppShell, router, navigation, PlaceholderPage
├── features/         # разделы продукта
│   ├── asset-registry/   # срез: дерево + таблица + детали + CRUD-формы
│   ├── settings/         # диалог системных настроек (режим хранения, сброс)
│   ├── dashboard/ asset-search/ strategies/ rounds/
│   └── criticality/ status-schemes/ catalogs/   # заглушки
└── main.tsx          # точка входа (RouterProvider)
```

Алиас `@/*` → `src/*` (см. `vite.config.ts` и `tsconfig.app.json`).

## Заметки

- Конкретные версии библиотек проверяются через **Context7** непосредственно перед
  реализацией; ставим последние стабильные.
- Режим «База данных» и реальный бэкенд — вне рамок v1.
- Выбор отдельных библиотек (дерево, графики) можно скорректировать на старте, не
  меняя общей архитектуры.
