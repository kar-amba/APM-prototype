# Core Beliefs — операционные принципы

> Опинионированные, по возможности механические правила, которые держат
> репозиторий понятным и согласованным для будущих запусков агентов. Это «golden
> principles» проекта. Держим список коротким и применимым.

## 1. Репозиторий — источник истины

Если знание не лежит в репозитории в виде версионируемого артефакта (код,
markdown, схема, план), для агента оно не существует. Любую важную договорённость
переноси в репозиторий.

## 2. AGENTS.md — карта, а не энциклопедия

Точка входа короткая и стабильная, с указателями на детали. Не раздуваем её:
большой монолит вытесняет полезный контекст и быстро устаревает.

## 3. Планы — артефакты первого класса

Нетривиальную работу фиксируем в `docs/exec-plans/`. Маленькие изменения —
лёгкий план; сложные — план с журналом решений и прогресса. Завершённое
переносим в `completed/`.

## 4. Документация поддерживается актуальной

Меняешь поведение — обновляешь документ. Стале́ный документ хуже отсутствующего:
он вводит в заблуждение. Помечай статус (см. `index.md`).

## 5. Симуляция вместо реальных интеграций

В прототипе любая «интеграция» — локальный симулятор. Не добавляем реальные
внешние подключения без явного запроса.

## 6. Скучные и понятные технологии

Предпочитаем стабильные, хорошо документированные решения, которые легко
полностью осмыслить в пределах репозитория. Меньше «магии» — больше предсказуемости.

## 7. Валидируем границы данных

Не угадываем форму данных «на глаз». Описываем типы/контракты на границах
(ввод форм, моки, симуляторы), чтобы не строить логику на догадках.

## 8. Сохраняем существующую структуру

Не перемещаем и не удаляем существующие файлы и каталоги без явного указания.

## 9. Единый визуальный язык

Вся визуальная часть следует дизайн-системе `docs/brandbook-template.html`.

## 10. Граница изменений

CI/CD, автолинтеры и автоматизированные проверки пока сознательно не настроены —
вводим их отдельным осознанным шагом.
